# Homework04 博客系统学习笔记

> 这是一个完整的 Go Web 后端项目，适合刚开始学习 Go 的开发新手。通过这个项目，你可以学习到 Web 开发的核心概念和 Go 语言的实际应用。

## 一、项目概述

### 1.1 这个项目是什么？
这是一个**个人博客系统的后端 API**，实现了用户注册、登录、发布文章、评论等功能。

**简单理解：**
- 就像你用的微信公众号、知乎、简书这些平台
- 但这个是你自己写的后端服务
- 前端（网页、APP）可以通过这些接口来操作数据

### 1.2 项目技术栈
```
Go 1.24          - 编程语言
Gin              - Web 框架（处理 HTTP 请求）
GORM             - 数据库操作工具（ORM）
SQLite           - 轻量级数据库
JWT              - 用户认证（Token）
bcrypt           - 密码加密
```

### 1.3 实现的功能
- ✅ 用户注册（密码加密存储）
- ✅ 用户登录（生成 Token）
- ✅ 发布文章（需要登录）
- ✅ 修改/删除文章（只能修改自己的）
- ✅ 查看文章列表和详情（公开）
- ✅ 发表评论（需要登录）
- ✅ 查看评论列表

## 二、项目结构设计思路

### 2.1 为什么要分这么多文件夹？

```
homework04/
├── main.go           # 程序入口，路由配置
├── models/           # 数据模型（定义数据结构）
├── database/         # 数据库连接和初始化
├── handlers/         # 处理业务逻辑（Controller）
├── middleware/       # 中间件（权限验证）
└── test/            # 测试代码
```

**类比理解：**
- **main.go** - 像是餐厅的大门，客人（请求）进来后，要分配到不同的服务员
- **models/** - 像是菜单，定义了有哪些菜（数据结构）
- **database/** - 像是厨房的冰箱，存储所有的食材（数据）
- **handlers/** - 像是厨师，根据客人点的菜来制作（处理业务逻辑）
- **middleware/** - 像是门卫，检查客人是否有会员卡（权限验证）

### 2.2 为什么要这样分层？

**好处：**
1. **代码更清晰** - 每个文件负责一件事，容易找到要改的地方
2. **便于维护** - 修改数据库不影响业务逻辑，修改业务逻辑不影响路由
3. **方便测试** - 可以单独测试某个功能模块
4. **团队协作** - 不同人可以同时开发不同模块

## 三、核心概念详解（萌新必看）

### 3.1 什么是 HTTP 和 RESTful API？

**HTTP** 就是浏览器和服务器通信的语言：
```
客户端（浏览器）  →  发送请求  →  服务器
客户端（浏览器）  ←  返回响应  ←  服务器
```

**常见的 HTTP 方法：**
- `GET` - 获取数据（查看文章列表）
- `POST` - 创建数据（注册用户、发布文章）
- `PUT` - 更新数据（修改文章）
- `DELETE` - 删除数据（删除文章）

**RESTful API 风格：**
```
GET    /posts          # 获取所有文章
GET    /posts/1        # 获取 ID=1 的文章
POST   /posts          # 创建新文章
PUT    /posts/1        # 更新 ID=1 的文章
DELETE /posts/1        # 删除 ID=1 的文章
```

### 3.2 什么是 JSON？

JSON 是前后端传递数据的格式，像是一种"数据快递包装"：

```json
{
  "username": "testuser",
  "password": "123456",
  "email": "test@example.com"
}
```

**类比：** 就像填表格，键（key）是表格的标题，值（value）是你填的内容。

### 3.3 什么是数据库和 ORM？

**数据库：** 存储数据的地方（像是一个超级 Excel 表格）

```
users 表：
ID | username | password  | email
1  | zhangsan | ******    | zhang@example.com
2  | lisi     | ******    | li@example.com
```

**ORM（GORM）：** 让你用 Go 代码操作数据库，不用写 SQL

```go
// 不用写 SQL: SELECT * FROM users WHERE username = 'zhangsan'
// 直接用 Go 代码：
db.Where("username = ?", "zhangsan").First(&user)
```

### 3.4 什么是 JWT 认证？

**问题：** 用户登录后，下次请求怎么知道这是同一个人？

**解决方案：** 登录成功后给用户一个"令牌"（Token）

```
1. 用户登录 → 服务器生成 Token
2. 用户下次请求带上这个 Token
3. 服务器验证 Token，确认身份
```

**Token 长这样：**
```
eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9.eyJpZCI6MSwidXNlcm5hbWUiOiJ0ZXN0In0...
```

### 3.5 为什么要加密密码？

**危险做法：** 直接存储明文密码
```
username: zhangsan
password: 123456    ← 数据库被黑，密码泄露！
```

**安全做法：** 使用 bcrypt 加密
```go
// 注册时加密
hashedPassword, _ := bcrypt.GenerateFromPassword([]byte("123456"), bcrypt.DefaultCost)
// 存储: $2a$10$TtSgpZB5zYrW3T2BARZHx.uaHaIOEBryn1Kq/Sjhdux8uyB6s69We

// 登录时验证
bcrypt.CompareHashAndPassword(hashedPassword, []byte("123456"))  // 对比是否匹配
```

## 四、代码实现详解

### 4.1 数据模型设计 (models/models.go)

```go
type User struct {
    gorm.Model              // 自动包含 ID, CreatedAt, UpdatedAt, DeletedAt
    Username string `gorm:"unique;not null"`
    Password string `gorm:"not null"`
    Email    string `gorm:"unique;not null"`
}
```

**gorm.Model 包含什么？**
```go
ID        uint           // 主键，自动递增
CreatedAt time.Time      // 创建时间
UpdatedAt time.Time      // 更新时间
DeletedAt *time.Time     // 删除时间（软删除）
```

**为什么用软删除？**
- 删除数据时不真正删除，只标记 DeletedAt
- 可以恢复数据，可以查看历史记录
- 查询时 GORM 会自动过滤掉已删除的数据

### 4.2 数据库初始化 (database/db.go)

```go
func InitDB() {
    // 1. 连接数据库
    DB, err = gorm.Open(sqlite.Open("blog.db"), &gorm.Config{})
    
    // 2. 自动创建表结构
    DB.AutoMigrate(&models.User{}, &models.Post{}, &models.Comment{})
}
```

**AutoMigrate 做了什么？**
- 检查表是否存在，不存在就创建
- 检查字段是否匹配，不匹配就更新
- **注意：** 不会删除已有的字段

### 4.3 用户注册流程 (handlers/auth.go)

```go
func Register(c *gin.Context) {
    // 1. 接收前端传来的 JSON 数据
    var input struct {
        Username string `json:"username" binding:"required"`
        Password string `json:"password" binding:"required"`
        Email    string `json:"email" binding:"required,email"`
    }
    c.ShouldBindJSON(&input)
    
    // 2. 密码加密
    hashedPassword, _ := bcrypt.GenerateFromPassword([]byte(input.Password), bcrypt.DefaultCost)
    
    // 3. 保存到数据库
    user := models.User{
        Username: input.Username,
        Password: string(hashedPassword),
        Email:    input.Email,
    }
    database.DB.Create(&user)
    
    // 4. 返回成功响应
    c.JSON(http.StatusCreated, gin.H{"message": "User registered successfully"})
}
```

**gin.H 是什么？**
- 它是 `map[string]interface{}` 的别名
- 用来快速构建 JSON 响应
```go
gin.H{"message": "success"}  
// 等同于
// map[string]interface{}{"message": "success"}
```

### 4.4 JWT 认证中间件 (middleware/auth.go)

```go
func AuthMiddleware() gin.HandlerFunc {
    return func(c *gin.Context) {
        // 1. 从请求头获取 Token
        authHeader := c.GetHeader("Authorization")
        // 格式: "Bearer eyJhbGciOiJIUzI1NiIs..."
        
        // 2. 解析 Token
        token, err := jwt.Parse(tokenString, func(token *jwt.Token) (interface{}, error) {
            return SecretKey, nil
        })
        
        // 3. 验证成功，保存用户信息到上下文
        c.Set("userID", uint(userIDFloat))
        c.Set("username", claims["username"])
        
        // 4. 继续处理后续请求
        c.Next()
    }
}
```

**为什么用 c.Set() 和 c.Get()？**
- 在中间件中保存信息，后续处理函数可以取出使用
- 避免重复查询数据库

### 4.5 文章权限控制 (handlers/post.go)

```go
func UpdatePost(c *gin.Context) {
    // 1. 获取当前登录用户的 ID（从中间件保存的）
    userID, _ := c.Get("userID")
    
    // 2. 查询文章
    var post models.Post
    database.DB.First(&post, id)
    
    // 3. 验证是否是作者本人
    if post.UserID != userID.(uint) {
        c.JSON(http.StatusForbidden, gin.H{"error": "You are not the author"})
        return
    }
    
    // 4. 更新文章
    database.DB.Model(&post).Updates(input)
}
```

## 五、路由设计思路 (main.go)

```go
func main() {
    r := gin.Default()
    
    // 公开路由（不需要登录）
    r.POST("/register", handlers.Register)
    r.POST("/login", handlers.Login)
    r.GET("/posts", handlers.GetPosts)
    r.GET("/posts/:id", handlers.GetPost)
    
    // 受保护的路由（需要登录）
    posts := r.Group("/posts")
    posts.Use(middleware.AuthMiddleware())  // 使用认证中间件
    {
        posts.POST("", handlers.CreatePost)
        posts.PUT("/:id", handlers.UpdatePost)
        posts.DELETE("/:id", handlers.DeletePost)
    }
    
    r.Run(":8080")
}
```

**路由分组的好处：**
- 相同的路径前缀只写一次
- 统一应用中间件
- 代码更清晰

## 七、常见问题解答

### Q1: 为什么要用 `c.ShouldBindJSON()` 而不直接解析？
```go
// 不推荐的方式
body, _ := ioutil.ReadAll(c.Request.Body)
json.Unmarshal(body, &user)

// 推荐的方式（Gin 封装好的）
c.ShouldBindJSON(&user)
```
**原因：**
- `ShouldBindJSON` 会自动验证字段（binding 标签）
- 自动处理错误
- 代码更简洁

### Q2: `gin.H` 和 `struct` 返回 JSON 有什么区别？
```go
// 方式1: gin.H（灵活，适合简单响应）
c.JSON(200, gin.H{"message": "success"})

// 方式2: struct（规范，适合复杂数据）
type Response struct {
    Message string `json:"message"`
}
c.JSON(200, Response{Message: "success"})
```

### Q3: 什么时候用 `First`、什么时候用 `Find`？
```go
// First - 查询一条记录（返回第一条）
db.First(&user, 1)  // 找不到会报错 ErrRecordNotFound

// Find - 查询多条记录（返回数组）
db.Find(&users)     // 找不到返回空数组，不报错
```

### Q4: `c.Param` 和 `c.Query` 有什么区别？
```go
// URL: /posts/123?page=1

// c.Param - 路径参数
id := c.Param("id")  // "123"

// c.Query - 查询参数
page := c.Query("page")  // "1"
```
